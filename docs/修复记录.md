## 2026-10-19 增量（第二轮）：球差模拟 + 后台渲染

### 新增：球差（Spherical Aberration）控制

散景的核心是“离焦光斑长什么样”，而球差正是决定它的关键像差：欠校正的镜头把光线能量推到光斑边缘，过校正则堆到中心。本轮把这个机制接进引擎。

- 引擎新增 `EngineSettings.spherical`（-1 ~ +1），对弥散圆/散景做**径向能量再分配**：
  - `>0` 欠校正 → 能量聚到边缘（边缘亮环、硬朗的“肥皂泡”散景）；
  - `<0` 过校正 → 能量聚到中心（中心亮、柔和的奶油散景）；
  - `0` 校正良好 → 均匀圆盘。
- 卷积 PSF 归一化后再使用，**总光量守恒**（球差是重新分配能量，不改变整体曝光）。
- 同时作用于两处：背景虚化的光圈 PSF（`_disc_kernel` / `_disc_blur_levels`）与高光光斑的绘制（`_bokeh_overlay`：欠校正加粗并提亮边缘、过校正压暗边缘并叠加亮心）。
- 界面在「镜头与虚化」新增「球差」滑块（-100 ~ +100，默认 0，带悬浮说明）。
- 实测：三种球差下 PSF 总和恒为 `1.0000`；径向质心 **欠校正 ≈ 0.77 > 校正 ≈ 0.65 > 过校正 ≈ 0.48**（均匀圆盘理论值 2/3），方向正确；出图形态 +1 亮环暗心 / -1 亮心暗边 / 0 均匀，与光学预期一致。

### 修复：渲染在主线程执行导致界面「无响应」

- **现象**：拖动滑块（尤其切到“高质量预览（原尺寸）”）、打开大图、或导出大图时窗口卡死，Windows 标记为“未响应”。
- **根因**：`engine.process()` 全程在 Qt 主线程同步执行。实测单次耗时：1000px 预览 0.30 s、1400px 0.41 s、24MP 约 4.5 s；最坏（3000×2000 + 500 高光 + 3× 抗锯齿）5.3 s，24MP 导出外推 ≈ 20 s+。**与新增的球差无关**：开关球差前后 1000px 预览为 0.30 s vs 0.31 s，属噪声级。
- **修复**：`engine.process()` 移到独立 `RenderWorker(QThread)`；预览请求自动合并（只保留最新一条），导出请求排队不丢弃；导出等待改用嵌套 `QEventLoop` 并加 60 s 超时兜底，等待期间 GUI 事件循环照常运转；关闭窗口时安全停止渲染线程，自检入口先 `close()`。
- **实测**：导出 1200×1800 结果正常；导出执行期间主线程定时器仍在触发（测得 19 次回调）→ 界面保持响应；透明图层导出返回 `(final, effect, alpha)` 三张；`python app\main.py --selftest` 退出码 0。

源码改动仅限 `app/engine.py`（球差）与 `app/main.py`（球差滑块 + 渲染线程），未新增依赖。

## 2026-10-19 增量（第四轮）：圆形光斑修正 + 主体边缘 / 深度分辨率 / 配置记忆 / 可滚动控制栏

### 修复：圆形光斑不够圆

- **原因**：光斑绘制中的「猫眼压缩」强度是写死的（`squash = 1 - 0.45·edge²`）。画面中心的光斑本来是正圆，但越靠近画面边缘被横向压扁得越厉害（实测边缘处宽高比只有约 0.55），于是看起来"不够圆"。
- **修复**：把猫眼强度做成可调（`EngineSettings.cat_eye`，0~1），**默认 0 → 所有光斑都是正圆**；新增「猫眼压缩」滑块（0~100）给需要机械暗角观感的用户自行调高。实测边缘光斑宽高比：`cat_eye=0 → 1.000`、`0.3 → 0.928`、`1.0 → 0.735`。

### 新增：主体边缘调整

- `EngineSettings.subject_expand`（-1~1）对清晰主体遮罩做收缩/扩张（最长边最多 ±1.2%，上限 ±30px）；`subject_feather`（0~1）对遮罩做高斯羽化。
- 界面对应「主体边缘（-100~+100）」与「边缘羽化（0~100）」，用来把深度模型在轮廓处留下的一圈光晕收进去或柔化掉。
- 实测（2000×3000）：默认 0.95 s，`expand=+1` 1.20 s，`feather=1` 0.74 s，开销可接受。

### 新增：深度图生成分辨率

- **关键发现**：`transformers` 深度 pipeline 的 `preprocess(image, timeout=None)` 不接受 `size`，`_sanitize_parameters` 会把 `size` 静默丢弃 —— 走 pipeline 无法控制推理分辨率。
- 因此绕开 pipeline，直接用 `AutoImageProcessor` + `AutoModelForDepthEstimation`，把 `size` 传给 processor（对齐到 14 的倍数），不被支持时回退到模型默认分辨率。
- 界面新增「深度图分辨率」：518（模型原生）/ 756 / 1036 / 1260。
- 实测（Small，CPU）：`size=0` 与 `size=518` 输出一致（约 0.2 s），`size=1036` 输出明显不同、耗时 1.18 s → 分辨率确实生效。

### 新增：配置记忆

- 关闭窗口时把全部设置（光圈、各滑块、光斑形状、对焦模式、深度分辨率、所选模型、窗口几何等）写入 `settings.ini`，下次启动自动恢复。
- **注意**：本机 Windows 注册表不可写（`QSettings` NativeFormat 返回 `AccessError`），所以改用 `QSettings` 的 **IniFormat** 显式文件；优先放在程序目录，目录只读时回退到用户配置目录。`settings.ini` 已加入 `.gitignore`。
- 实测：写入 8 项后新建窗口读回全部一致。

### 新增：控制面板可滚动

- 控制列包进 `QScrollArea`（`widgetResizable`，隐藏水平滚动条），控件继续增加也不会被窗口截断；滚动条沿用既有 QSS 样式。

本轮改动集中在 `app/engine.py`、`app/depth_worker.py`、`app/main.py`、`app/theme/app.qss.tmpl` 与 `.gitignore`，未新增依赖；`main.py --selftest` 退出码 0。

## 2026-10-19 增量（第五轮）：圆形光斑棱角 + 控制面板横向裁切

> 修正第四轮的判断：用户说的"光斑不圆"指的是**边缘出现多边形棱角**，不是猫眼造成的椭圆压扁。第四轮的「猫眼压缩」可调仍然保留（默认 0＝正圆），但真正的问题在本轮修复。

### 修复：圆形光斑边缘呈多边形（棱角）

- **根因**：虚化卷积核 `_disc_kernel` 用 `cv2.circle` 栅格化 —— 半径小的时候是方块，半径 9px 时放大后明显是**八边形**；此外绘制光斑用的多边形只取 48 个采样点。卷积核本身不是真圆，背景虚化的光斑自然带棱角。
- **修复**：圆形光圈（`blade_count < 3`）的卷积核改为**解析距离场**生成（`kernel = clip(radius + 0.5 - dist, 0, 1)`，自带 1px 抗锯齿边缘），任意半径都是真圆；`_aperture_points` 的圆形分支采样点 48 → 128。
- **实测**：`kernel_r9` 由八边形变正圆、`kernel_r3` 由方块变圆润；绘制光斑 `drawn_circle` 为光滑正圆，`drawn_7blade` 仍为规则七边形（设计预期）。

### 修复：控制面板横向空间被遮挡（标签被裁）

- **根因**：控制列里的长下拉框（对焦模式、AI 模型、预览质量、深度分辨率）按内容撑宽（`QComboBox` 默认 `AdjustToContentsOnFirstShow`），把整个表单的最小宽度顶大；超过滚动区可视宽度后，左侧标签列被裁掉（截图里只剩数值与滑块）。
- **修复**：面板内所有 `QComboBox` 统一改为 `AdjustToMinimumContentsLengthWithIcon` + `minimumContentsLength = 8`，最小宽度不再由内容决定；滚动区横向策略改为 `AsNeeded`，列宽 300–400。
- **实测**：980×680 下滚动区可视宽 286px、内容最小宽 266px → 内容可容纳，横向滚动条不出现；抓图确认各表单标签完整显示。

本轮改动：`app/engine.py`（`_disc_kernel` / `_aperture_points`）与 `app/main.py`（下拉框宽度策略 + 滚动策略），未新增依赖；`main.py --selftest` 退出码 0。

## 2026-10-20 增量（第六轮）：修复 exe 报 “No module named 'torch'” + AI 版打包

### 修复：已在 venv 装了 AI 依赖，exe 仍报 No module named 'torch'

- **根因**：PyInstaller 冻结出的 exe 是**自包含**的，运行时**不会读取 `.venv` 的 site-packages**。轻量版打包时脚本显式 `--exclude-module torch/transformers`，所以即使用户通过 `install_ai_windows.bat` 在 venv 里装好 torch，exe 依然找不到 —— 报 `No module named 'torch'`。
- **修复**：
  1. 用 `tools/build_exe.py --clean --with-ai` 重新打包，把 torch/transformers 打进包里；
  2. 在 `build_exe.py` 的 AI 分支补上 `--collect-submodules transformers` 与 `--hidden-import torch / tokenizers / safetensors / huggingface_hub`（AI 的 import 写在函数内懒加载、transformers 又动态解析模型类，只靠静态分析可能漏收）。
- 附带问题：第一次重新打包失败的直接原因是 `dist\伯爵大光圈模拟` 被**正在运行的旧 exe** 占用（PyInstaller 清理输出时 `WinError 5 / 32`）；结束该进程后重新打包即通过。
