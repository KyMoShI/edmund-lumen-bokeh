## 2026-11-17：顶部统计区与通道直方图

- 直方图底色统一为预览占位区域的浅灰色 `#E6E6E6`，柱条保持白色；未导入图片时不绘制提示文字，保留空白统计区域及禁用的通道按钮。
- 浅色参数卡片顶部此前由 `_Metadata.paintEvent` 读取 `before_canvas._pixmap` 并按覆盖比例绘制照片，既未连接直方图组件，也未使用像素统计。这是照片出现在统计区域的直接原因。现将上方内容替换为共享直方图，原拍摄信息条继续按 EXIF 四列或尺寸、格式两列显示；源稿锚点和外框测量保持独立记录。
- 增加共享 `HistogramModel`，一次统计当前预览图的 256 档亮度、红、绿、蓝计数，支持亮度和三个单通道视图。亮度沿用 `cv2.COLOR_RGB2GRAY` 的编码值换算，不将其表述为线性光亮度；RGB 计数直接来自预览 RGB 字节。浅色顶部、黑夜卡片及独立窗口共用计数与当前通道，切换通道不重新统计。
- 通道入口仅保留图表右上角的 R / G / B 方形按钮，尺寸 26 × 26 逻辑 px、圆角 5 px、间隔 6 px，距顶边和右边各 6 px；常态黑底 `#262626` 白字，选中蓝底 `#001EFF` 白字。三个按钮互斥，点击已选按钮取消，全部未选时回到亮度；模型键分别为 `luminance`、`red`、`green`、`blue`。
- 图表统一灰底白条，不显示标题、坐标文字、通道说明和图例；窗口标题及菜单仍为「图像直方图」。内部统计范围为 0–255，柱高按当前通道峰值归一化。统计随有效处理结果更新，原图对比时使用原图，效果范围红色显示层不参与统计。无图或撤销至空图时清空计数和照片信息，禁用通道按钮，重新导图后恢复操作并保留通道偏好。
- `tools/check_histogram.py` 三按钮专项在 100% / 150% / 200% 缩放下通过，验证原始及分块 RGBA 精确计数、互斥与再次点击取消、按钮几何和状态色、跨视图同步、原图对比、范围标记排除、浮动及主题往返和空图恢复。界面截图见[工作区顶部统计](../design-system/baoyue-bokeh/pages/workspace-histogram.png)和[四种通道状态](../design-system/baoyue-bokeh/pages/histogram-channels.png)。下方 2026-11-16 的缩略图描述为当时实现记录，本节取代其作为当前顶部内容定义。

## 2026-11-17：欢迎页标题时序与卡片滚动

- 欢迎页标题采用两阶段状态：逐字显示「伯爵大光圈」，首句完成后按实际时间保留 3000 ms，再清空并逐字显示「今天我们要模拟什么」；完成后在文本末尾以约 500 ms 间隔切换竖线光标。停留时间不受全局动画速度缩放，第二句字号按原品牌文字矩形适配，黑色品牌条及菱形装饰保持原几何。
- 动画总开关或标题开关关闭时，直接显示静态第二句和常显白色光标，停止闪烁定时器。等待及逐字完成状态停止高频打字更新；3 秒等待使用单次定时器，动态光标使用低频定时器。隐藏页面或开始导航时取消待触发状态，避免离开后更新隐藏标题。该时序取代早期单句完成即停止全部标题更新的调度方式。
- 卡片滚轮使用 easeOutCubic 曲线，连续滚轮输入在目标位置上累积，并按滚动范围限制；触控板的 `pixelDelta` 直接跟随。滚动条拖动、分组定位等外部位置修改以及隐藏部件会取消未完成目标，避免缓动覆盖明确操作。浅色参数卡片、浮动窗口及黑夜控制总区复用同一规则，遵循动画总开关、速度与更新间隔；禁用动画后直接应用滚动位置。
- 「焦点景深」附加参数展开采用 OutCubic 缓出曲线，沿用已有动画配置。展开后的分组定位会取消旧滚动目标，避免滚轮动画将内容移出刚定位的位置。
- 滚动控制器跟踪当前有效的 Qt 滚动条及视口，在对象替换后重建事件及信号绑定；窗口销毁期间停止定时器，避免浮动归位后访问已失效的 C++ 对象。专项检查覆盖滚动条替换、已销毁对象取消，以及完整参数卡片反复浮动、归位后的滚轮与显式定位。
- `tools/check_card_motion.py` 的 10 组专项与完整工作区的 16 组集成回归均在 100% / 150% / 200% 缩放下通过，统一二级窗口检查通过；欢迎页和直方图专项也覆盖相同三档缩放。首句及布局参考见[欢迎页](../design-system/baoyue-bokeh/pages/welcome.png)，提示语状态见[欢迎页提示](../design-system/baoyue-bokeh/pages/welcome-prompt.png)。

## 2026-10-19 球差模拟 + 后台渲染

### 新增：球差（Spherical Aberration）控制

该版本使用径向权重控制普通模式的光斑亮度分布。参数符号约定及测量结果如下。

- 引擎新增 `EngineSettings.spherical`（-1 \~ +1），对弥散圆/散景做**径向能量再分配**：

  - `>0` 欠校正 → 能量聚到边缘（边缘亮环、硬朗的“肥皂泡”散景）；

  - `<0` 过校正 → 能量聚到中心（中心亮、柔和的奶油散景）；

  - `0` 校正良好 → 均匀圆盘。

- 卷积 PSF 归一化后再使用，**总光量守恒**（球差是重新分配能量，不改变整体曝光）。

- 同时作用于两处：背景虚化的光圈 PSF（`_disc_kernel` / `_disc_blur_levels`）与高光光斑的绘制（`_bokeh_overlay`：欠校正加粗并提亮边缘、过校正压暗边缘并叠加亮心）。

- 界面在「镜头与虚化」新增「球差」滑块（-100 \~ +100，默认 0，带悬浮说明）。

- 实测：三种球差下 PSF 总和恒为 `1.0000`；径向质心 **欠校正 ≈ 0.77 > 校正 ≈ 0.65 > 过校正 ≈ 0.48**（均匀圆盘理论值 2/3），方向正确；出图形态 +1 亮环暗心 / -1 亮心暗边 / 0 均匀，与光学预期一致。

### 修复：渲染在主线程执行导致界面「无响应」

- **现象**：拖动滑块（尤其切到“高质量预览（原尺寸）”）、打开大图、或导出大图时界面线程阻塞，Windows 显示「未响应」。

- **根因**：`engine.process()` 全程在 Qt 主线程同步执行。实测单次耗时：1000px 预览 0.30 s、1400px 0.41 s、24MP 约 4.5 s；最坏（3000×2000 + 500 高光 + 3× 抗锯齿）5.3 s，24MP 导出外推 ≈ 20 s+。**与新增的球差无关**：开关球差前后 1000px 预览为 0.30 s vs 0.31 s，属噪声级。

- **修复**：`engine.process()` 移到独立 `RenderWorker(QThread)`；预览请求自动合并（只保留最新一条），导出请求排队不丢弃；导出等待改用嵌套 `QEventLoop` 并加 60 s 等待超时，等待期间 GUI 事件循环照常运转；关闭窗口时安全停止渲染线程，自检入口先 `close()`。

- **实测**：导出 1200×1800 结果正常；导出执行期间主线程定时器仍在触发（测得 19 次回调）→ 界面保持响应；透明图层导出返回 `(final, effect, alpha)` 三张；`python app\main.py --selftest` 退出码 0。

## 2026-10-19 圆形光斑修正 /主体边缘 / 深度分辨率 / 配置记忆 / 可滚动控制栏

### 变更：猫眼压缩强度可调

- **原因**：光斑绘制中的「猫眼压缩」强度为固定值（`squash = 1 - 0.45·edge²`）。画面中心的光斑本来是正圆，但越靠近画面边缘横向收窄幅度越大（实测边缘处宽高比只有约 0.55），导致边缘光斑呈椭圆形。

- **修复**：把猫眼强度做成可调（`EngineSettings.cat_eye`，0–1），默认 0 时关闭猫眼压缩；新增「猫眼压缩」滑块（0–100）。实测边缘光斑宽高比：`cat_eye=0 → 1.000`、`0.3 → 0.928`、`1.0 → 0.735`。

### 新增：主体边缘调整

- `EngineSettings.subject_expand`（−1 至 +1）对清晰主体遮罩做收缩/扩张（最长边最多 ±1.2%，上限 ±30px）；`subject_feather`（0–1）对遮罩做高斯羽化。

- 界面对应「主体边缘（-100\~+100）」与「边缘羽化（0\~100）」，用来把深度模型在轮廓处留下的一圈光晕收进去或柔化掉。

- 实测（2000×3000）：默认 0.95 s，`expand=+1` 1.20 s，`feather=1` 0.74 s。

### 新增：深度图生成分辨率

- **关键发现**：`transformers` 深度 pipeline 的 `preprocess(image, timeout=None)` 不接受 `size`，`_sanitize_parameters` 会把 `size` 静默丢弃 —— 走 pipeline 无法控制推理分辨率。

- 因此绕开 pipeline，直接用 `AutoImageProcessor` + `AutoModelForDepthEstimation`，把 `size` 传给 processor（对齐到 14 的倍数），不被支持时回退到模型默认分辨率。

- 界面新增「深度图分辨率」：518（模型原生）/ 756 / 1036 / 1260。

- 实测（Small，CPU）：`size=0` 与 `size=518` 输出一致（约 0.2 s），`size=1036` 输出明显不同、耗时 1.18 s → 分辨率确实生效。

### 新增：配置记忆

- 关闭窗口时把全部设置（光圈、各滑块、光斑形状、对焦模式、深度分辨率、所选模型、窗口几何等）写入 `settings.ini`，下次启动自动恢复。

- **注意**：本机 Windows 注册表不可写（`QSettings` NativeFormat 返回 `AccessError`），所以改用 `QSettings` 的 **IniFormat** 显式文件；优先放在程序目录，目录只读时回退到用户配置目录。`settings.ini` 已加入 `.gitignore`。

- 实测：写入 8 项后新建窗口读回全部一致。

### 新增：控制面板可滚动

- 控制列包进 `QScrollArea`（`widgetResizable`，隐藏水平滚动条），控件继续增加也不会被窗口截断；滚动条沿用既有 QSS 样式。

## 2026-10-19 圆形光斑棱角 + 控制面板横向裁切

> 本轮处理圆形卷积核栅格化导致的多边形棱角。上一轮新增的猫眼压缩仍作为独立控制项。

### 修复：圆形光斑边缘呈多边形（棱角）

- **根因**：虚化卷积核 `_disc_kernel` 用 `cv2.circle` 栅格化 —— 半径小的时候是方块，半径 9px 时放大后明显是**八边形**；此外绘制光斑用的多边形只取 48 个采样点。卷积核本身不是真圆，背景虚化的光斑自然带棱角。

- **修复**：圆形光圈（`blade_count < 3`）的卷积核改为**解析距离场**生成（`kernel = clip(radius + 0.5 - dist, 0, 1)`，自带 1px 抗锯齿边缘），减小小半径卷积核的栅格棱角；`_aperture_points` 的圆形分支采样点 48 → 128。

- **实测**：`kernel_r9` 由八边形变正圆、`kernel_r3` 由方块变圆润；绘制光斑 `drawn_circle` 为光滑正圆，`drawn_7blade` 仍为规则七边形（设计预期）。

### 修复：控制面板横向空间被遮挡（标签被裁）

- **根因**：控制列里的长下拉框（对焦模式、AI 模型、预览质量、深度分辨率）按内容撑宽（`QComboBox` 默认 `AdjustToContentsOnFirstShow`），把整个表单的最小宽度顶大；超过滚动区可视宽度后，左侧标签列被裁掉（截图里只剩数值与滑块）。

- **修复**：面板内所有 `QComboBox` 统一改为 `AdjustToMinimumContentsLengthWithIcon` + `minimumContentsLength = 8`，最小宽度不再由内容决定；滚动区横向策略改为 `AsNeeded`，列宽 300–400。

- **实测**：980×680 下滚动区可视宽 286px、内容最小宽 266px → 内容可容纳，横向滚动条不出现；抓图确认各表单标签完整显示。

## 2026-10-20 效果范围 / 高光补偿 / 直方图 + 两处修复

### 修复：切换「显示原图」会重置缩放

- **现象**：放大看细节后点「显示原图」，视图跳回全图。
- **根因**：`toggle_original` 每次都走 `set_image()` → `set_source_pixmap()`，而后者无条件把 `_zoom` 置 1.0、`_pan` 置 0。
- **修复**：`set_source_pixmap` / `set_image` 增加 `keep_view` 参数；切换对比与刷新渲染结果都传 `keep_view=True`，换图与换预览尺寸仍按默认复位。双击预览仍可作为显式复位入口。

### 修复：导出后未能唤起文件管理器

- **根因**：原实现 `subprocess.Popen(["explorer", ...])` 依赖 PATH 解析，且 `except OSError: pass` 未向界面报告失败——冻结成 exe 或 PATH 异常时既不唤起也无提示。
